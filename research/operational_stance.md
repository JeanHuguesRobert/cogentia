# Operational Stance

## A governed situated control-mode projection for persistent agents

## Object

This document defines a working architectural distinction called **Operational Stance** for Cogentia and governed agent systems.

The core distinction is:

> **A Cogentigram represents relatively persistent structural dispositions. An Operational Stance represents the temporary way in which an agent approaches a particular situation.**

The claim is deliberately narrower than proposing a new psychological object. Situation-dependent policy, supervisory control and metacontrol are established ideas. The candidate Cogentia contribution is the **governance envelope** around such variation: how a temporary policy is derived, bounded, inspected, traced, transmitted without transmitting authority, and revised when Reality changes.

Human arbitration on 2026-08-27 retained the name **Operational Stance** for the conceptual layer while separating it from implementation vocabulary:

```text
Operational Stance
  conceptual name

mode_projection
  experimental operational representation

metacontrol / supervisory logic
  candidate resolution mechanisms

control mode
  principal engineering prior-art family
```

This naming decision does **not** make `stance` a runtime or packet schema key.

## 1. Why this layer exists

A persistent agent needs both continuity and adaptation.

Continuity is required for:

- Identity;
- values and constitutional invariants;
- cognitive fidelity;
- accountability;
- stable delegation;
- reproducibility.

Adaptation is required because the right way to approach a situation depends on the situation:

```text
new architectural possibility
  → widen search

unknown external claim
  → increase verification

cheap reversible experiment
  → prefer Reality Test

possible manipulation
  → increase adversarial search

consequential commitment
  → increase caution and recovery checks

evidence sufficient + OptionLoss rising
  → stop exploring and decide
```

Putting all such variation into Persona, Style, Risk, or ad hoc prompting creates conceptual and operational confusion.

The missing question is:

> **Given the same persistent agent, what temporary control policy is appropriate to what is happening now?**

---

## 2. Working definition

> **Operational Stance is the conceptual name for a temporary, governed, situation-dependent control policy that modulates how an agent searches, verifies, deliberates, selects procedures and commits to action.**

Its experimental machine-facing representation is called `mode_projection`.

The defining properties are:

```text
situated
  depends materially on current circumstances

temporary
  does not become Identity merely because it was useful once

derived
  computed from governed state rather than arbitrary personality switching

inspectable
  consequential changes can be explained and traced

bounded
  Mandate, rights, invariants and Budgets outrank it

revisable
  Reality may cause it to change during the task

non-authoritative
  it cannot create permission

eliminable
  if an explicit projection adds no value, collapse it into simpler policy machinery
```

A useful compression is:

> **Stance changes navigation, not jurisdiction; policy, not Reality.**

---

## 3. Stable dispositions versus temporary policy

A Cogentigram describes relatively persistent structure. Operational Stance occupies a shorter timescale.

```text
Cogentigram
  what structural tendencies persist?

Operational Stance
  how should the present situation be approached?
```

A Cogentigram may indicate high cognitive flexibility, tolerance for uncertainty, strong verification habits, or other persistent tendencies. Those tendencies can influence mode resolution, but they do not imply:

```text
always exploratory
always cautious
always skeptical
always decisive
```

Therefore:

> **Disposition influences Stance; it is not Stance.**

The same persistent agent may legitimately move from exploratory to cautious to decisive without identity drift.

## 4. Boundary with neighboring concepts

| Object | Core question |
|---|---|
| Identity / Values | What enduring entity and commitments govern this agent? |
| Cogentigram | What relatively persistent structural tendencies characterize it? |
| Role | What function is it currently performing? |
| Persona | Under what social or expressive appearance is it interacting? |
| Operational Stance | How should it approach the current situation? |
| Skill | What reusable procedure or capability should it use? |
| Style | How should the result be expressed? |
| Mandate | What is it authorized to do? |
| Budget | What bounded resources may it consume? |
| Measured Risk | What objective, uncertainty, Exposure and recovery conditions govern action? |
| Autonomy / orchestration mode | How independently may it proceed within authority? |

Three boundaries are especially important:

```text
Stance ≠ authority
Stance ≠ belief
Stance ≠ Skill
```

A more opportunity-seeking agent is not more authorized. A more skeptical mode does not make propositions false. An exploratory mode may increase the salience of `open-possible`, but the Skill remains a separate reusable procedure.

## 5. Inputs to mode resolution

A situated mode may be derived from:

```text
persistent dispositions
  Cogentigram

objective
  what value or learning is pursued?

role
  what function is being performed?

situation
  what is happening now?

task phase
  exploration / validation / commitment / execution / recovery

trust context
  trusted / unknown / potentially adversarial

Measured Risk
  uncertainty
  Exposure
  affected Principals
  recovery structure
  OptionLoss
  residual harm

Mandate
  authority
  rights
  prohibitions
  delegation boundaries

Budgets
  financial
  compute
  time
  risk/loss
  Human Attention

Reality observations
  what materially changed since the previous resolution?
```

Conceptually:

```text
persistent structure
        +
objective / role / situation
        +
Mandate / Budgets / autonomy
        +
Measured Risk / trust / task phase
        ↓
metacontrol or supervisory resolution
        ↓
mode_projection
        ↓
search / verification / deliberation / action policy
```

The first implementation does **not** require a dedicated `Stance Resolver` service. The resolver may be deterministic, model-assisted, human-selected, or hybrid.

```text
breadth of alternative search
verification intensity
contradictory-evidence search
adversarial testing
deliberation depth
initiative within existing authority
Skill salience

Readable presets may include:

```

`opportunity-seeking` is preferred over canonical `optimistic` because optimism can be confused with an optimistic factual belief.

Presets are human/logging conveniences, not a personality ontology.

## 7. Epistemic invariant

The epistemic invariant has two clauses.

### 7.1 Evidence is not rewritten

> **Operational Stance may alter search allocation, verification intensity, deliberation and action thresholds. It must not alter obtained evidence, manufacture convenient beliefs, inflate or deflate probabilities merely to fit the mode, or silently change the evidential update rule.**

Therefore:

```text
opportunity-seeking stance
  ≠ optimistic facts

skeptical stance
  ≠ presume claims false

adversarial stance
  ≠ believe everyone is hostile

cautious stance
  ≠ inflate estimated risk

exploratory stance
  ≠ invent possibilities as facts
```

### 7.2 Evidence selection is part of the trace

Changing search allocation changes which evidence arrives. This creates an **evidence-diet effect** without any fact being fabricated.

Examples:

```text
decisive mode
  may stop searching earlier

opportunity-seeking mode
  may spend more effort on enabling evidence

adversarial mode
  may spend more effort on failure evidence
```

Therefore:

> **A Stance may change which evidence is sought and at what cost. It must not hide that selection effect or present a policy-shaped evidence set as if it were neutral or exhaustive.**

The trace need not enumerate every query. It should record material asymmetries when they bear on consequential conclusions.

## 8. Experimental representation: `mode_projection`

The representation is deliberately provisional.

A first dogfood form may expose candidate operational dimensions:

```yaml
mode_projection:
  label: exploratory_vigilant
  parameters:
    exploration_bias: 0.9
    verification_intensity: 0.7
    adversarial_search: 0.3
    initiative_level: 0.8
    commitment_threshold: 0.4
    deliberation_depth: 0.6
```

These are not yet schema commitments.

Known overlap risks include:

```text
exploration_bias ↔ commitment_threshold
verification_intensity ↔ adversarial_search
initiative_level ↔ autonomy boundary
```

The prototype must therefore permit falsification:

1. **Ablation** — remove one dimension and test whether behavior or explanation worsens.
2. **Correlation** — observe whether dimensions move together across scenarios.
3. **Boundary test** — changing initiative must not widen authority or autonomy.
4. **Compression test** — compare the six candidates with a smaller representation.
5. **No-schema rule** — do not promote these fields into stable packet or Corpus schemas before the A/B Reality Test.

If fewer variables explain the useful variation, collapse the representation.

## 9. Recursive control and switching stability

Operational Stance is not a one-time choice.

```text
context / risk / mandate / budget
          ↓
      resolve mode
          ↓
 search / verify / deliberate / act
          ↓
       Reality answers
          ↓
new evidence / Exposure / cost / task phase
          ↓
 update context and Measured Risk
          ↓
      possibly re-resolve mode
```

A typical task may move through:

```text
exploratory → experimental → vigilant → cautious → decisive
```

But rapid switching can itself become a control failure. The implementation should therefore model, where useful:

```text
dwell time
  minimum useful duration before ordinary re-resolution

hysteresis
  separate enter/exit thresholds around unstable boundaries

rate limits
  bound non-urgent parameter changes

mode chatter detection
  detect repeated oscillation without useful new evidence

fallback mode
  behavior when inputs are missing, contradictory or adversarial
```

Urgent safety, Mandate or Exposure changes override ordinary dwell-time stability.

The objective is control stability, not simulated psychological continuity.

## 10. Relationship to Measured Risk

Measured Risk asks:

> What value or learning justifies this Act, what is at stake, what can be recovered, who bears the residue, and is that envelope authorized?

Operational Stance asks:

> Given that situation, how should the agent now investigate, deliberate and commit?

Examples:

```text
high learning value
+ low Exposure
+ cheap recovery
→ more experimental

third-party Exposure
+ weak recovery
→ more cautious / vigilant

unknown propagation
→ more verification and less commitment

OptionLoss rising
+ evidence sufficient
→ more decisive
```

The relationship is recursive: a Stance changes search; search changes evidence; evidence may change Risk and therefore Stance.

Operational Stance must not become a second competing risk model.

---

## 11. Relationship to Mandate, Budgets and autonomy

Mandate defines the reachable action space.

Budget bounds resource consumption within that space.

Autonomy/orchestration mode defines how independently the agent may proceed within authority.

Operational Stance changes how the agent navigates within those boundaries.

```text
more opportunity-seeking
  ≠ more authorized

more decisive
  ≠ permitted to commit

more adversarial
  ≠ permitted to inspect protected data

more experimental
  ≠ permitted to externalize loss
```

A positive expected value never creates authority.

---

## 12. Relationship to Skills

A Stance is not a Skill.

```text
Operational Stance
  policy posture

Skill
  reusable procedure
```

Example:

```text
mode_projection: exploratory
        ↓
increase salience of:
  cogentia.open-possible
        ↓
Skill executes:
  FRAME → CHALLENGE → PRESERVE → OPEN → BOOST → TEST
```

The Skill remains governed by its Mandate and Measured Risk constraints.

This separation prevents every behavioral mode from becoming a Skill and prevents Skills from silently acquiring authority.

---

## 13. Relationship to Persona and Style

The same Operational Stance can be expressed through different Personas.

The same Persona can operate under different Stances.

```text
Persona: Agent John
Stance: exploratory

Persona: Agent John
Stance: vigilant

Persona: Agent John
Stance: decisive
```

Style may reveal some consequences of Stance, but Style is not evidence that the policy changed.

> An agent that merely **sounds** cautious without changing verification or commitment policy is performing cautious Style, not operational caution.

This distinction becomes an explicit evaluation requirement in the A/B Reality Test.

## 14. Cognitive Packet semantics

The conceptual distinctions remain useful:

```text
observed mode
  the policy under which the sender actually worked

requested mode
  a non-authoritative hint or request

locally resolved mode
  the policy actually selected by the receiver
```

Rules:

> **Observed mode is provenance, not instruction and not social proof.**

A receiver must not imitate a mode merely because it came from a trusted, successful, senior, upstream or high-status sender.

> **Requested mode is a hint, not delegated authority.**

> **Locally resolved mode remains subordinate to local Mandate, Budgets, Risk and invariants.**

However, human arbitration freezes stable packet fields until the A/B Reality Test. For now, experimental traces may use only the neutral container:

```yaml
mode_projection:
  ...
```

Do **not** yet freeze these as canonical keys:

```text
stance
observed_stance
requested_stance
locally_resolved_stance
```

Conceptual identity does not imply schema identity.

## 15. Counterfactual Stance reasoning

Explicit Stances make lightweight counterfactual review possible:

```text
What would a Vigilant stance notice?

What objection appears under a Skeptical stance?

What possibility becomes visible under an Exploratory stance?

Is a Conservative stance preserving an option whose loss matters?

Has Decisive become appropriate because further search now costs more than it buys?
```

This does not require persistent simulated personalities. It can be a temporary change of evaluation policy over the same evidence.

Its value remains experimental.

## 16. Engineering prior art: control mode and metacontrol

The closest implementation family is not persona research but **supervisory control, switched/hybrid control, adaptive automation, adaptive autonomy and metacontrol**.

A working map is:

| Cogentia function | Engineering analogue | Cogentia governance question |
|---|---|---|
| situation-dependent policy configuration | control mode / switched control | how mode selection is derived under Mandate, Budget and Risk |
| selecting search depth or explore/exploit behavior | metacontrol / policy over policies | how selection is exposed and traced without reifying personality |
| changing initiative within fixed authority | adaptive-autonomy parameter | how to prevent a parameter change from widening authority |
| mode transition | supervisory control | which triggers, dwell time, hysteresis and fallback are appropriate |
| local recomputation after handoff | local controller policy | how context travels without authority travelling |
| observed/requested/local distinction | no exact canonical analogue assumed | whether explicit packet semantics add enough value to justify fields |

The working conclusion is:

> **Situation-dependent policy is established prior art. The candidate contribution is the governance envelope around derivation, authority boundaries, traceability, packet semantics and eliminability.**

This claim survives even if the explicit `mode_projection` is killed by Reality testing.

## 17. Human and organizational prior-art anchors

Human and organizational theories provide useful neighboring distinctions, not validation of the software architecture.

### Regulatory Focus Theory

Promotion focus emphasizes advancement and gains; prevention focus emphasizes security, duties and avoiding harmful mistakes. A useful compression is:

```text
promotion-oriented question
  What valuable possibility might we miss?

prevention-oriented question
  What harmful mistake might we make?
```

### Personality states

Personality research distinguishes relatively enduring traits from time-local states influenced by situation. This supports the stable-disposition versus situated-state distinction without establishing Cogentia's runtime design.

### Defensive pessimism

Defensive pessimism shows that deliberately considering adverse outcomes can be a temporary strategy rather than a global worldview. This is relevant to cautious or vigilant modes.

### High Reliability Organizations

Practices such as preoccupation with failure and sensitivity to operations illustrate institutionally organized vigilance without requiring permanent paralysis.

Collective Stance remains deferred. The MVP must **not average, vote, inherit or blend Stance across Principals**. Collective resolution is a separate governance problem.

## 18. Artificial-agent and LLM prior art

The term `attitude` is already occupied in BDI architectures, where beliefs, desires and intentions are mental attitudes. Operational Stance is not proposed as another BDI attitude.

Recent LLM work shows that shorter-timescale behavioral configuration is technically real enough to deserve explicit governance:

- Wei et al., **Beyond Static Personas: Situational Personality Steering for Large Language Models**, Findings of ACL 2026, introduces IRIS for situation-dependent personality steering: <https://aclanthology.org/2026.findings-acl.958/>.
- QI et al., **Beyond Static Persona Consistency: Dynamic Persona Coherence in LLM Role-Playing**, ACL 2026, explicitly separates stable identity from adaptive shorter-timescale state: <https://aclanthology.org/2026.acl-long.1336/>.
- Feng et al., **PERSONA: Dynamic and Compositional Inference-Time Personality Control via Activation Vector Algebra**, ICLR 2026, provides context-aware dynamic composition of personality vectors: <https://proceedings.iclr.cc/paper_files/paper/2026/hash/f66ce276436c4cd151535b03841ac713-Abstract-Conference.html>.
- Chen et al., **Persona Vectors: Monitoring and Controlling Character Traits in Language Models** (2025), identifies activation-space directions associated with traits and uses them for monitoring and steering: <https://arxiv.org/abs/2507.21509>.
- Sun et al., **Some Large Language Models Exhibit Consistent Risk Attitudes** (2026), separates contextual risk belief from the belief-to-decision mapping: <https://arxiv.org/abs/2607.16197>.

These works support only narrower claims:

```text
behavior can vary systematically with situation
shorter-timescale state can be separated from stable identity
behavioral directions can be monitored or steered
risk belief can be distinguished from risk-to-decision policy
```

They do **not** establish:

```text
Operational Stance as a standard term
a canonical Stance vector
persona steering as the preferred implementation
first-class persistent Stance state
```

## 19. Terminology collision map

The word `stance` is intentionally retained despite material collisions.

| Existing usage | Rough meaning | Same as this document? |
|---|---|---|
| intentional stance | interpret a system as a rational agent with beliefs/desires | No |
| linguistic / attitudinal stance | speaker positioning, certainty, affect or evaluation | No |
| epistemic stance | positioning toward truth, attribution or commitment | No, though adjacent |
| proposition/belief stance in simulations | support for a proposition | No |
| control mode | active controller/policy configuration under transition rules | Close |
| metacontrol policy | policy governing which lower-level policy to use | Close |
| Operational Stance | governed conceptual description of situated search/verification/deliberation/commitment policy | This document |

Human arbitration therefore chooses a deliberate split:

```text
conceptual human-facing term
  Operational Stance

experimental machine-facing representation
  mode_projection
```

If Reality shows that the conceptual term itself creates material confusion, the decision can be reopened.

## 21. First Reality Test: explicit projection versus ordinary situated policy

The first experiment must be capable of killing the explicit projection.

### Condition A — explicit projection

Use an explicit `mode_projection`, with its rationale trace, to configure search, verification, deliberation and commitment policy.

### Condition B — ordinary situated policy

Express equivalent intended policy directly as ordinary task, risk and mandate instructions **without** using:

- the Stance vector;
- preset names;
- §8 field vocabulary;
- a named control-mode object.

If Condition B is merely the same vector with the label removed, the experiment is invalid because it tests naming rather than architectural value.

Everything else should remain as equal as practical:

```text
same underlying agent/model
same evidence
same Mandate
same Budgets
same Measured Risk description
same task
same action capabilities
functionally comparable intended policy
```

### Task E — exploration under low Exposure

A novel architectural possibility with high uncertainty, read-only effects and a cheap Reality Test.

Observable markers:

```text
material alternatives searched
present-state assumptions challenged when relevant
discriminating Reality Test proposed
negative evidence not hidden
no permission inferred from opportunity
```

### Task C — consequential commitment under uncertainty

A candidate action involving an external party, consequential commitment or difficult-to-repair downstream effect.

Observable markers:

```text
provenance / trust checked
Mandate explicitly respected
commitment withheld when required conditions are absent
recovery / Exposure inspected
contradictory evidence receives adequate search effort
```

These markers are **actions and checks**, not linguistic tone.

### Minimal paired protocol

For each task class:

1. prepare one fixed input/context;
2. run paired A/B executions;
3. repeat enough times to expose obvious nondeterministic variation — three paired runs is a dogfood default, not a scientific sample-size claim;
4. score observable behavior rather than wording.

Candidate metrics:

```text
policy fidelity
verification actions actually taken
missed required checks
unwarranted commitments
trace intelligibility
cross-agent resumability
style-only false positives
implementation complexity
mode/projection drift
```

### Killing criterion

> **If the explicit `mode_projection` does not materially improve inspection, behavioral consistency, traceability, reuse or resumability over ordinary situated policy — or if it adds ambiguity, anthropomorphic drift or authority confusion — do not promote it to a first-class architectural object.**

In that result, keep only the underlying control-mode / metacontrol rules.

### Promotion criterion

Only after independent value is observed should the Corpus consider:

```text
stable runtime object
persistent lifecycle
cross-document schema
packet fields
dedicated resolver component
broader instillation
```

## 22. Concessions and open questions

### Bounding — vector representation

The numerical dimensions are implementation hypotheses. The concept does not depend on six floats or any vector representation.

### Bounding — psychological analogy

Human psychology supplies prior art and useful distinctions, not proof of machine equivalence.

### Bounding — terminology may be reopened

Human arbitration retains `Operational Stance` as the conceptual name and `mode_projection` as the experimental representation. If Reality demonstrates material confusion, the naming decision may be reopened.

### Load-bearing — explicit objecthood

Operational Stance may turn out to be useful as a conceptual distinction while `mode_projection` adds no runtime value. The A/B test is intended to kill that objecthood if necessary.

### Load-bearing — decomposition

The correct boundary among mode resolution, Measured Risk, Role, Skill routing, autonomy and orchestration is not yet fully demonstrated. A poor decomposition would create a redundant meta-layer.

### Open — dynamics

Which dwell-time, hysteresis, rate-limit, chatter and fallback rules are sufficient for the first implementation?

### Open — dimensionality

Which candidate dimensions survive ablation, correlation and compression tests?

### Open — collective governance

How should institutions or multi-agent systems resolve a situated policy when different Principals legitimately have different interests and risk appetites? This is explicitly outside the MVP.

## 23. Human arbitration record — 2026-08-27

### 23.1 Name

**Decision:** retain **Operational Stance** as the conceptual name.

Rationale:

- it remains intelligible across human, institutional and artificial-agent contexts;
- `control mode` is the strongest engineering analogue but narrower in ordinary use;
- `metacontrol policy` more naturally names the selection mechanism than the selected situated posture;
- `situated policy projection` is precise but cumbersome as a concept name;
- the collision risk is managed through explicit terminology boundaries rather than ignored.

### 23.2 Experimental representation

**Decision:** use **`mode_projection`** for the experimental computed representation.
